# Requirements (CONFIRMED) - issue #1238

Source: Spec v1, https://github.com/taftary/astrolith/issues/1238#issuecomment-6699137379.
Owner confirmation: https://github.com/taftary/astrolith/issues/1238#issuecomment-6699456431.

Derived from the frozen approved specification, not a new version or a claim of
completed work. C1-C11 correspond to its acceptance criteria; C12-C20 preserve
the test-plan expectations; C21-C32 spell out supporting proof boundaries.
The specification is authoritative. Commit this file with the feature PR.

Runtime criteria require the validator's own documented public-interface runs,
actual input/observation traces, retained raw evidence and all-log scans. Unit
fixtures supplement rather than replace real application runs. Source inspection
establishes instrument provenance and scope, not an unexecuted runtime result.
The validator never writes code or takes pictures. Unavailable production moon
ground remains unavailable: this Issue builds testing mechanisms, not #1215's
gameplay or save format. Preparation, camera routes and hovering are never
counted as player travel, landing or persistence. A source checkout SHA alone is
not an attestation of the launched executable's source.

## Acceptance criteria

- [ ] C1: Opt-in and isolated. The documented public runner launches the real app, uses only disposable profiles, retains executable/fixture identities and bounded evidence, and cannot touch the real player's profile. Normal startup has no test driver/collector and unchanged gameplay, controls and Help. (judged by the validator from independent runner and normal-start runs, manifests, real-profile before/after fingerprints, startup registration evidence, input/Help regressions and profile/path refusal cases; no script probe)
- [ ] C2: Selectable, honest starting states. Existing generated moon identities, local approach coordinates and shared times are selectable and repeatable. The fixture set and boundary coverage in Spec v1 exist with actual type/radius/orbit/origin records. Invalid identities fail rather than choosing another body. Setup is not reported as movement or a completed feature action. (judged by the validator from independently repeated selected-moon launches and fixture enumeration, actual generation/manifests and explicit preparation traces, minimum-boundary checks and invalid-identity runs; no script probe)
- [ ] C3: Ordinary input and explicit phases. Keyboard/pointer/button/wheel actions use production handling. Preparation and measured actions are distinguishable, including single-process multi-visit suites; continuous journeys cannot hide repositioning. Restart begins from the loaded profile, not replayed setup. (judged by the validator from independent production-input traces, setup/action and multi-visit boundaries, restart-first observations, read-only instrumentation tests and source provenance of input dispatch; no script probe)
- [ ] C4: Trustworthy observations. Actual player/camera/support, local frame, gravity, sky/light/occlusion and production UI/save/quality state are observable with units/identity/time. Generic drawn-ground and frame-conversion measurements work on current planets and report missing moon ground honestly. A reference sphere, chosen moon or expected value cannot masquerade as actual support. (judged by the validator from independent planet/contact/frame/clock/UI runs and selected-moon flying observations, production-state provenance and required-unavailable negative cases, without equating geometric separation with drawn-ground clearance; no script probe)
- [ ] C5: Public-control persistence. In normal disposable profiles, independently exercise Save here/Go for all eight slots, mode/look, remembered player and Go to player, clock and Manual/Auto choices, normal Quit/restart and the three separate Reset scopes. Saved state is read by the production loader; unrelated preferences and the real profile are preserved. No production save semantics are changed to make a test succeed. (judged by the validator from its own public-control normal-profile sequences and restart-first evidence, normal file I/O and Quit records, all eight views, current production restore semantics, separate Reset cases and before/after unrelated-preference and real-profile comparisons; no script probe)
- [ ] C6: Compatibility and failure paths. Fresh/old-valid planet and space profiles, missing/damaged/unresolvable records and unrelated saved preferences can be tested reproducibly. Wrong expectations, required unavailable observations, invalid fixture/profile paths, malformed inputs, incomplete Quit, timeouts and missing evidence return non-success with partial logs. Existing output and unmarked/non-disposable profiles are refused without overwriting them. (judged by the validator from independent profile-fixture and negative runs with exact terminal reasons, retained partial evidence, original-output fingerprints and profile/path isolation tests; no script probe)
- [ ] C7: Integrated input profiling. Real-input and persistent-profile sessions retain correlated actions, per-frame intervals/work/waits, cold/warm readiness, quality and one-second working-set samples. The tool supports the 20-distinct-moon/five-system session and 20 Low/Normal/High changes with 8/64/128 MiB memory choices, without calling preparation travel or hovering landing. (judged by the validator from independently executed serial input/persistent-profile measurements and the single-process exploration suite, common frame/time IDs, actual fixture/quality/memory records and raw memory/timing series; no script probe)
- [ ] C8: Loading/resource lifetime evidence. Per-frame/event records and derived high-water summaries expose the queues, uploads/time shares/overruns, stale results, active/outgoing ownership, proxies, atlas descriptors/caches and retirement in Spec v1, including render-world versus main-world distinctions. Required missing/dropped data cannot produce a complete measurement result. (judged by the validator from independent cold/quality/resize/departure/return runs, retained per-frame/event records and recomputed high-water summaries, production counter/ownership provenance and missing/dropped-evidence negative cases; no script probe)
- [ ] C9: Conditions and build provenance. Evidence directly records comparison conditions and an executable-matching release-build record. A source/hash mismatch or missing/unequal required environment facts blocks a matched claim. Unavailable optional GPU/draw readings remain explicit, not zero. (judged by the validator from independent manifests, retained run-time condition observations and main-agent build records matched to executable hashes, plus mismatch/missing/unequal-condition cases and unavailable optional-counter records; no script probe)
- [ ] C10: Bounded overhead and compatibility. Collection meets the matched-pair overhead limits in Spec v1 with streamed bounded storage. Existing #1227 scenarios and #1087 route/profiling behavior remain usable and truthfully labeled. No new rendering feature, gameplay resource budget, compiler/engine pin or validator permission change is introduced. (judged by the validator from three serial 30/120-second collection-off/on pairs, median mean/p95 calculations, bounded-stream/overflow checks, independent existing input/route smoke runs and scope/dependency checks; no script probe)
- [ ] C11: Independently usable. The validator can run the documented positive and negative procedures without repository code edits or desktop control. Developer docs and docs/validator-capabilities.md record exactly what was independently demonstrated, including remaining moon-gameplay/visual limits. New capability proof is separate from future #1215 feature validation. (judged by the validator from its own documented commands, all retained positive/negative evidence, documentation/registry audit and explicit limits without asserting unbuilt moon gameplay or owner visual acceptance; no script probe)

## Test-plan expected results

- [ ] C12: T1: Real body movement is distinct from camera movement; identities/time/coordinates repeat; the moon remains honestly flying/without moon collision support before #1215. (judged by the validator from independent existing planet and repeated selected home-Moon starts, ordinary body/camera input traces, matching identity/frame/time observations and explicitly absent moon-contact evidence; no script probe)
- [ ] C13: T2: Actual generated facts and boundary-only data are distinguished, no universe mutation occurs, and an invalid identity fails explicitly. Future ground-feature data is unavailable until production supplies it. (judged by the validator from independent fixture listings and selected small/icy/hot/other-type/moon-rich/seam/pole approaches, the 20-moon/five-system manifest, generation regression/boundary checks and nonexistent-moon failure; no script probe)
- [ ] C14: T3: Production contact/up/gravity and local spot are observed separately from the view; conversions compare one frozen pose; ordinary motion is not counted as conversion error. Sky and missing-data records are truthful. (judged by the validator from independent existing-planet walking/jump/camera/local-frame-transition/sky-control runs, frozen-pose conversion records with metre/degree units and production source/geometry checks; no script probe)
- [ ] C15: T4: The production file is written/read; loaded state is observed before actions, saved views retain current mode/look behavior, Manual choice survives Auto, and the real profile is unchanged. No replayed setup manufactures persistence. (judged by the validator from public preference/view-slot/mode/clock/Go to player/Quit actions in a disposable normal profile, a later launch of that profile without placement, actual loaded/file state and isolation fingerprints; no script probe)
- [ ] C16: T5: Current compatibility/fallback and Reset scopes are observable through production controls, unrelated preferences survive, and no test implements moon-relative saving. (judged by the validator from independent old-valid planet/space and missing/damaged/unresolvable-record cases, separate public Reset player/Views Reset/Display Reset runs and normal restarts, plus production save-semantics scope checks; no script probe)
- [ ] C17: T6: Preparation versus input is explicit; actual identities, queues, transient resource high-water marks, ownership/retirement, timings and memory are retained. Missing moon ground is not converted into a landing success. A limit violation is reported, not repaired or hidden by the tools. (judged by the validator from its single-process 20-moon/five-system suite, 20 detail changes and 8/64/128 MiB controls, interruption/return and first-scene revisit, full preparation/event history and honest measured-limit/unavailable reports; no script probe)
- [ ] C18: T7: Direct conditions/build identity support comparisons, median overhead stays within the declared bounds, and raw stalls/sampling limits remain visible. The ordinary, uninstrumented startup remains unchanged. (judged by the validator from three independently executed serial matched collection-off/on pairs on the reference PC, 30-second warm-up/120-second scoring, raw timing and condition/build records, separate stall/sampling reports and normal startup checks; no script probe)
- [ ] C19: T8: Each negative case is non-success with its exact reason and partial evidence; no unrelated process, real profile or previous evidence is changed. Missing comparison conditions cannot create a matched-performance claim. (judged by the validator from independently run wrong/unavailable-observation, bad moon/profile, malformed, incomplete-Quit, inner/outer-timeout, missing-record, mismatched-build and existing-output cases, process ownership/cleanup records, isolation and retained-file comparisons; no script probe)
- [ ] C20: T9: Existing tools remain compatible; ordinary gameplay/menus/Help are unchanged; the new procedures are documented, independently usable and do not claim future moon landing, teleportation or visual acceptance. (judged by the validator from independently repeated legacy input/route smoke suites, an ordinary non-test launch, production control/Help comparisons and documentation/claim audit; no script probe)

## Supporting proof boundaries

- [ ] C21: Fixture coverage includes the home Moon, small generated moons near the current lower boundary, icy/hot and other actually generated types, another system, a moon-rich sky and at least 20 distinct moons across at least five systems. Record seed, host chain, permanent moon/host/system identity, actual type/radius/orbit, coordinate basis, shared time and origin/source; distinguish catalog-based home inputs, procedural instances/terrain and illustrative placement. The current radius draw is 200 km inclusive to 1700 km exclusive; exact-boundary data is labeled separately from a sampled moon, and finite search is not the universe's absolute minimum. (judged by the validator from independently enumerated/repeated fixture manifests, actual generator/classifier/catalog inputs and source references, uniqueness/system counts and explicit boundary tests/provenance labels; no script probe)
- [ ] C22: Every placement/reset used by a bounded multi-visit suite has an explicit preparation boundary in one process and remains in resource/peak accounting. After each preparation movement uses ordinary controls. Continuous journeys require input throughout. Restart observes loaded state before any preparation and cannot re-place the player, restore expected settings or reset time to manufacture success. (judged by the validator from independent multi-visit and normal-restart phase traces, correlated resource records including preparation, production input provenance and restart-first negative/positive checks; no script probe)
- [ ] C23: Actual supporting-body identity is distinct from a nearby/chosen moon. Drawn-ground clearance is distinct from reference-sphere separation. Local spot/up, actual gravity, surface recipe/material/atmosphere, shared-clock sky positions/angles/occlusion and light direction come from production state with units/time/frames. A frame conversion compares the same physical pose in metres and degrees for 1 cm / 0.05 degree checks, separating normal travel/sky motion. (judged by the validator from independent current-planet contact/frame/sky runs, moon-nearby flying evidence, matching frozen-pose conversion records and production observer/geometry provenance; no script probe)
- [ ] C24: UI observations report real settings/effective quality, all saved-view slots/mode/look, selected player, text/layout/clip/scroll bounds and actual control state. No field is copied from an assertion. Absent data has an explicit unavailable/not-applicable reason, never a plausible zero, and cannot satisfy required numeric/contact checks. (judged by the validator from independent real menu/scroll/save/quality/selection input runs at narrow/wide layouts, actual UI state/text/bounds records and unavailable/incorrect-assertion failures, supplemented by read-only observation tests; no script probe)
- [ ] C25: Explicit persistent testing uses the normal production loader/saver and input/evidence bridge only in a marked disposable profile. Existing no-file-I/O scenarios retain their meaning and records identify the mode. Test files may be seeded/copied only during initial preparation; measured save/recall/Go to player/Reset/Quit use public controls. Forced termination is not normal save/Quit success. Real-profile presence/hash stays unchanged on every exit and contents are not published. (judged by the validator from independent normal-profile and legacy in-memory runs, seeded/loaded/action ordering, real normal-Quit versus forced/incomplete-termination evidence, profile/symlink/path isolation failures and manifest/log privacy checks; no script probe)
- [ ] C26: Real-input/persistent sessions correlate actions, readiness, scene/support identity and quality/resolution with per-frame intervals, CPU work and waits. Loading records expose queued/in-flight/completed builds, uploads, application share/time/overruns, stale outcomes and resource ownership. Proxy vertices/logical buffers, mesh/material/submission groups, atlas page descriptors/allocated logical sizes, cache/caps, active/outgoing sets and actual retirement stages/high-water marks are retained, distinguishing render-world removal from main-world handle drops and logical bytes from total GPU allocation. (judged by the validator from independently measured input/persistence and cold/quality/memory/interrupt/return runs, frame/event witness provenance, raw records and recomputed resource summaries; missing required fields are not supplied by fictional game logs or optional unavailable GPU counters; no script probe)
- [ ] C27: One-second process working-set samples retain their gaps and acknowledge missed instantaneous peaks. Frame/event high-water records cover short-lived queue/atlas/ownership events. Summaries derive from raw records. Bounded buffers stream output rather than grow with run length; missing/dropped required records or an output/buffer limit produce incomplete non-success with partial evidence. Existing budget violations are reported, not repaired or hidden. (judged by the validator from independently collected memory/frame/event streams, high-water recomputation, cadence/gap/overflow/missing-record checks, bounded-buffer tests and honest baseline-violation reports; no script probe)
- [ ] C28: Run-time conditions record actual adapter/backend/driver, dimensions, refresh, AC/battery/power condition, workers and saved/effective graphics settings. Missing/unequal required facts prevent matched comparison; manually supplied facts link to retained observations from that run. The main-agent build record names command, source commit/tree/tracked state, toolchain, completion and executable hash, checked against the launched binary; checkout SHA alone is insufficient. No validator build or arbitrary-command permission is granted. (judged by the validator from actual run/build/condition artifacts and executable identity, independently exercised mismatch/unavailable/unequal-condition cases, and subprocess/permission scope checks; no script probe)
- [ ] C29: Collection-off/on overhead uses the same executable/settings/reference PC, three serial matched pairs with 30-second warm-up and 120 scored seconds each, comparing medians. Added mean interval is at most the larger of 1 ms or 5 percent, added p95 at most the larger of 2 ms or 5 percent. Stalls and sampling limits remain separate; these are tool-overhead bounds, not changed #1215 feature budgets. Evidence-size and bounded-run limits are documented. (judged by the validator from its independent matched-pair manifests and raw intervals, recomputed per-run and median comparisons against both absolute/relative bounds, stall/sampling disclosure and documented storage limits; no script probe)
- [ ] C30: Testing collection is explicitly opt-in, absent on ordinary startup even when a profiling environment variable is set, and cannot change game decisions or force quality. Existing scenario/route semantics and fail-closed completion remain usable; runner execution stays limited to the authorized application and necessary documented observation, not a general command wrapper or desktop controller. (judged by the validator from ordinary/environment-only/test launches, independent legacy/input/route runs, effective-quality/action records and startup/input/subprocess provenance checks; no script probe)
- [ ] C31: No moon terrain/collision/landing/walking, production moon-relative saves, Surface detail/Help changes, teleport/mini-map/discovery, universe-generation changes, rendering feature/budget change, pin change or validator permission expansion is introduced. Generic observations report today's planets and absent moon ground honestly; future gameplay may populate the production contract, not require hidden new drivers inside #1215. (judged by the validator from scope/notion checks, generation/production-behavior regression evidence, dependency/pin/permission comparisons and explicit observer unavailable results; no script probe)
- [ ] C32: Developer documentation and the capability registry describe only independently executed tools/procedures and their actual limits. Main-agent build/measurement work is distinguished from independent evidence. This prerequisite does not certify future #1215 moon gameplay, owner appearance/feel or #1226 teleport behavior; any remaining testing gap is recorded instead of silently substituting camera playback or unit tests. (judged by the validator from its own retained command/results compared with docs/registry statements and the explicit unavailable/future-work boundaries, without a circular requirement for a PR verdict to exist first; no script probe)
